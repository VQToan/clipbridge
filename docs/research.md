# ClipBridge — Research Report

> Ngày: 2026-11-10 · Mục tiêu: clipboard đồng bộ liền mạch giữa **Android, iOS, macOS, Linux**, hỗ trợ **text + image**.

---

## 1. TL;DR

| Kết luận | Chi tiết |
|---|---|
| **Desktop (macOS, Linux) có thể tự động 100%** | Đọc/ghi clipboard nền được. macOS cần user bấm "Allow" một lần (Pasteboard Privacy). Linux Wayland cần compositor hỗ trợ `ext/wlr-data-control` (GNOME là ngoại lệ). |
| **Android: ghi nền OK, đọc nền bị chặn từ Android 10** | Cần chiến lược: **IME (bàn phím riêng)**, **Quick Settings Tile**, **Share target / PROCESS_TEXT**, hoặc chế độ power-user qua ADB/Shizuku. |
| **iOS là nút thắt lớn nhất** | Không có background execution → **không thể tự động đọc/ghi clipboard nền**. "Liền mạch" trên iOS = **1 thao tác** (Keyboard extension, Share extension, Shortcuts/Action Button, widget, `UIPasteControl`). |
| **Sync layer** | Cần **E2EE**; kết hợp **LAN direct** (nhanh, offline) + **relay internet** (khác mạng) + **push (APNs/FCM)** để đánh thức mobile. |
| **Stack đề xuất** | **Rust core** (crypto, protocol, storage, sync) + **native shells** (SwiftUI cho iOS+macOS, Kotlin/Compose cho Android, Rust daemon cho Linux) + **Go relay server**. |

> [!IMPORTANT]
> Không sản phẩm nào (kể cả Apple Universal Clipboard) đạt "tự động hoàn toàn" trên iOS với app bên thứ 3. Thiết kế UX phải chấp nhận điều này ngay từ đầu, thay vì hứa hẹn rồi vỡ.

## 2. Ràng buộc từng nền tảng

### 2.1 macOS
- **Đọc**: `NSPasteboard.general` + poll `changeCount` (~300–500ms; không có event API chính thức). Đây là cách Maccy, Raycast, Paste dùng.
- **Pasteboard Privacy** (preview từ macOS 15.4, enforce ở các bản mới hơn): đọc payload không có user action → alert *"App X would like to paste from App Y"*.
  - `NSPasteboard.accessBehavior` để biết trạng thái (`default/ask/allow/deny`).
  - Các API **detect** (kiểm tra type/pattern) **không** kích hoạt alert → dùng để lọc trước khi đọc.
  - User cấp "Allow" tại *System Settings › Privacy & Security › Paste from Other Apps*. Reset: `tccutil reset Pasteboard <bundle_id>`.
- **Ghi**: tự do (`clearContents` + `writeObjects`).
- **Image**: `public.png`, `public.tiff`, `public.jpeg`, `public.heic` → chuẩn hoá về PNG/WebP khi gửi.
- **Concealed/Transient types**: tôn trọng `org.nspasteboard.ConcealedType`, `TransientType`, `AutoGeneratedType` (password manager đánh dấu) → **không sync**.
- Phân phối: menu-bar app (LSUIElement), login item qua `SMAppService`.

### 2.2 Linux
| Môi trường | Cơ chế đọc nền | Ghi chú |
|---|---|---|
| **X11** | XFixes `SelectionNotify` (event-driven) | Dễ, crate `x11rb` / `arboard`. |
| **Wayland – wlroots (Sway, Hyprland, niri, labwc…)** | `ext-data-control-v1` / `wlr-data-control-unstable-v1` | Event-driven, không cần focus. Crate `wl-clipboard-rs`. |
| **Wayland – KDE Plasma** | Hỗ trợ data-control (Plasma 6) | Klipper song song, cần tránh loop. |
| **Wayland – GNOME (Mutter)** | **Không** hỗ trợ data-control | Phải viết **GNOME Shell extension** nhỏ (JS) làm cầu nối qua D-Bus, hoặc fallback XWayland (hạn chế). |

- Ghi chú quan trọng: trên Wayland, khi app nguồn đóng thì selection mất → daemon phải **giữ ownership** khi ghi (serve data liên tục).
- MIME: `text/plain;charset=utf-8`, `image/png`, `x-kde-passwordManagerHint` (= `secret` → không sync).
- Chạy dưới dạng **systemd user service** + tray (`ksni` – StatusNotifierItem).

### 2.3 Android
- **Android 10+ (API 29)**: `getPrimaryClip()` trả `null` nếu app **không có focus** và **không phải IME mặc định**.
- **Ghi** clipboard từ background: **được phép** (có toast hệ thống "copied" từ Android 13).
- Android 13+: nên gắn `ClipDescription.EXTRA_IS_SENSITIVE` cho dữ liệu nhạy cảm; và tôn trọng cờ này khi đọc → không sync.

Chiến lược đọc (xếp theo độ "liền mạch"):

| # | Cách | UX | Rủi ro |
|---|---|---|---|
| 1 | **Custom IME** (bàn phím riêng, hoặc chỉ dùng như clipboard keyboard) | Tự động khi đang dùng bàn phím đó | User phải đổi bàn phím — rào cản lớn |
| 2 | **Quick Settings Tile** → mở Activity trong suốt 1 frame → đọc → đóng | 1 chạm từ notification shade | An toàn, Play-compliant |
| 3 | **Share target** + **`ACTION_PROCESS_TEXT`** (menu bôi đen text) | 1–2 chạm | Chuẩn, an toàn |
| 4 | **Persistent notification action "Send clipboard"** | 1 chạm | Cần trampoline Activity để có focus |
| 5 | **Power-user**: ADB/Shizuku cấp `appops READ_CLIPBOARD allow` / `READ_LOGS` để phát hiện thay đổi | Tự động | Không ổn định giữa các bản Android/OEM, không thể làm mặc định |
| ✗ | Overlay focus-steal, Accessibility Service | — | **Vi phạm Play policy**, không dùng |

- Nhận dữ liệu: **FCM high-priority** hoặc kết nối foreground service (`dataSync` type, Android 14 có giới hạn thời gian) → ghi thẳng vào clipboard.

### 2.4 iOS / iPadOS
- **Không có background execution liên tục** → không thể watch clipboard, không thể ghi clipboard khi app không chạy.
- **iOS 16+**: đọc `UIPasteboard` bằng code → prompt *"Allow Paste"*; user có thể set *Allow* trong Settings › App › Paste from Other Apps. `hasStrings`/`hasImages`/`detectPatterns` **không** prompt.
- `UIPasteControl` (iOS 16+): nút paste hệ thống → không prompt.

Chiến lược:

| Chiều | Cách | UX |
|---|---|---|
| **Gửi đi** | **Share Extension** (text/ảnh từ mọi app) | 2 chạm |
| | **App Intent + Shortcuts** gắn **Action Button / Back Tap / Control Center control** (iOS 18) → "Get Clipboard" → gửi | **1 chạm vật lý, gần như liền mạch** ✅ |
| | Mở app → tự đọc (khi đã set Allow) → gửi | 1 lần mở app |
| **Nhận về** | **Custom Keyboard Extension** (Full Access) hiển thị lịch sử đã sync → chạm để chèn text / copy ảnh | Liền mạch khi gõ ✅ |
| | **Push notification** (APNs) → user chạm → app mở & ghi clipboard | 1 chạm |
| | **Interactive Widget / Control** (`Button(intent:)`) → copy item mới nhất | 1 chạm |
| | **Live Activity** hiển thị clip mới nhất trên Lock Screen/Dynamic Island | Nhìn thấy, 1 chạm để copy |

> [!WARNING]
> Keyboard extension giới hạn bộ nhớ (~48–70MB) → không được nhúng runtime nặng (Flutter/React Native). Rust core + Swift là lựa chọn an toàn. Cần PoC xác nhận ghi `UIPasteboard` từ widget/notification extension trên iOS hiện hành.

## 3. Các giải pháp hiện có (benchmark)

| Sản phẩm | Nền tảng | Kiến trúc | Ưu | Nhược |
|---|---|---|---|---|
| **Apple Universal Clipboard** | Apple only | iCloud + BLE/Wi-Fi | Liền mạch thật | Khoá trong hệ Apple |
| **KDE Connect** | Android, Linux, Win, macOS (iOS yếu) | LAN P2P, TLS | Mature, nhiều tính năng | Chỉ LAN; Android 10+ phải bấm tay; iOS kém |
| **ClipCascade** | Android, iOS, Linux, macOS, Win | Self-hosted server (Java) hoặc P2P, E2EE | Gần ý tưởng nhất, text+image+file | UX iOS vẫn bị giới hạn; server Java nặng |
| **LocalSend** | Mọi nền tảng | LAN HTTP(S), Flutter | UX đẹp | Là file-sharing, không phải clipboard sync |
| **Join (joaoapps)**, **Pushbullet** | Android, desktop | Cloud | Có push | Không open, không E2EE mặc định, iOS hạn chế |
| **Samsung/Microsoft Phone Link** | Android ↔ Windows | Vendor privileged | Liền mạch | Cần quyền hệ thống OEM |

**Khoảng trống thị trường**: một sản phẩm **E2EE, LAN-first + relay**, UX iOS được thiết kế quanh Keyboard/Action Button/Live Activity, desktop native nhẹ, có self-host server.

## 4. Lựa chọn công nghệ

### 4.1 Client framework

| Tiêu chí | **A. Rust core + Native UI** (đề xuất) | B. Flutter + Rust (FRB) | C. Tauri 2 (web UI) | D. Kotlin Multiplatform |
|---|---|---|---|---|
| Chia sẻ logic | Rust core cho cả 4 | Dart/Rust | Rust | Kotlin (Linux desktop qua JVM) |
| iOS Keyboard/Share ext | ✅ Swift + Rust nhỏ gọn | ⚠️ Phải viết Swift riêng, khó share Dart | ⚠️ Viết Swift riêng | ⚠️ Kotlin/Native vào ext được nhưng nặng |
| Android IME/Tile/Service | ✅ Kotlin native | ⚠️ Plugin native | ⚠️ Plugin native | ✅ |
| Linux daemon + tray, Wayland | ✅ Rust thuần | ⚠️ Flutter Linux + daemon riêng | ✅ | ⚠️ JVM nặng cho daemon |
| macOS menu-bar nhẹ | ✅ SwiftUI `MenuBarExtra` | ⚠️ | ✅ | ⚠️ Compose Desktop (JVM) |
| Số codebase UI | 3 (SwiftUI dùng chung iOS+macOS) | 1 (+ native ext) | 1 (+ native ext) | 1–2 |
| Môi trường máy hiện có | ✅ cargo, go, Xcode | ❌ chưa có Flutter | ✅ | ⚠️ |

**Lý do chọn A**: 70% giá trị của app nằm ở **tích hợp OS** (pasteboard watcher, IME, extension, tray) — vốn phải viết native trong mọi lựa chọn. UI thực chất nhỏ (history list, pairing QR, settings). Rust core đảm bảo crypto/protocol **chỉ có 1 implementation** → không lệch giữa các nền tảng.

### 4.2 Transport / Sync

| Phương án | Ưu | Nhược |
|---|---|---|
| **Central relay (Go WebSocket)** | Đơn giản, offline mailbox, gắn được APNs/FCM | Phụ thuộc server, latency qua internet |
| **iroh (Rust, QUIC P2P)** | Direct LAN + hole punching + relay fallback, khoá Ed25519 = danh tính thiết bị | Không có mailbox offline, không push; mobile cần thử nghiệm |
| **Hybrid (đề xuất)** | iroh cho đường dữ liệu (LAN/direct) + Go server cho **push wake-up + mailbox E2EE + blob store ảnh** | Phức tạp hơn — chia phase |

> Phase 1 nên bắt đầu với **Go relay** (nhanh ra MVP, cần cho iOS push anyway), Phase 2 bổ sung **LAN direct qua iroh/mDNS**.

### 4.3 Bảo mật
- **Pairing** bằng QR code (chứa public key + device ID + relay URL), xác thực SAS 6 số như Signal/KDE Connect.
- **Device group key** (symmetric, XChaCha20-Poly1305) phân phối qua X25519 khi pair → server chỉ thấy ciphertext.
- Không sync: dữ liệu đánh dấu concealed/sensitive/password manager; app nằm trong danh sách loại trừ (macOS/Linux).
- Lịch sử lưu cục bộ SQLite (SQLCipher hoặc mã hoá field), TTL mặc định (vd. 24h, cấu hình được).

### 4.4 Xử lý ảnh
- Chuẩn hoá: decode mọi định dạng → gửi **PNG** (lossless) nếu ≤ ngưỡng, ngược lại **WebP/JPEG q85**; giữ bản gốc tuỳ chọn.
- Giới hạn mặc định: 20MB/item; ảnh lớn tách **blob** (upload chunked lên server/S3, envelope chỉ chứa hash + key).
- Thumbnail 256px cho history UI & keyboard extension (tiết kiệm RAM).
- Dedupe + chống vòng lặp: **BLAKE3 hash** nội dung; bỏ qua thay đổi clipboard do chính app ghi vào (so hash + cờ origin).

## 5. Rủi ro chính

| Rủi ro | Mức | Giảm thiểu |
|---|---|---|
| iOS không thể tự động hoàn toàn | Cao | Thiết kế UX quanh Keyboard + Action Button + Live Activity; truyền thông rõ ràng |
| App Store review (keyboard Full Access, clipboard privacy) | Trung bình | Privacy manifest rõ, không đọc clipboard khi chưa có hành động user |
| Play Store policy (background clipboard) | Trung bình | Chỉ dùng IME/Tile/Share; ADB mode để ngoài store hoặc ẩn trong advanced |
| GNOME Wayland | Trung bình | GNOME Shell extension riêng |
| Vòng lặp sync / echo | Trung bình | Hash + origin device ID + Lamport clock |
| Rò rỉ dữ liệu nhạy cảm (mật khẩu, OTP) | Cao | Tôn trọng concealed flags, exclusion list, TTL, E2EE |
